# feat: 결제 승인 중단 복구와 환불 결과 조회 복구

## 목적

결제 시작 기록 후 중단된 승인을 PG 상태에 따라 이어갑니다.
환불은 PG 결과를 먼저 확인하고, 완료 여부가 불확실하면 재전송을 보류하며 확인 필요 사유를 남깁니다.

## 변경 사항

- GET·POST 재요청·스케줄러에서 PG 승인 대기 상태를 확인하면 결제 시작 후 10분 이내에 기존 식별자로 승인 재시도
- 10분 이후 승인 재시도는 중단하고 결과 조회·좌석 보호 유지
- 환불 실행권과 최초 전송 기록으로 중복 전송을 막고, 만료된 실행자의 결과 저장 차단
- `PENDING`·`FAILED` 환불의 결과 조회를 계속하고, 완료 결과를 검증하는 `finishClaim()`으로 저장 경로 통일
- 환불 오류 분류·확인 필요 사유·발생 및 해결 시각 저장과 커밋 후 구조화 로그 추가
- V11~V13 마이그레이션 추가. 기존 환불은 전송 이력이 있을 수 있어 최초 전송 대상에서 제외

## 설계 판단

- **PG 조회에서 미취소라고 해도 재전송 가능하다고 단정하지 않습니다.** 최초 전송 이후에는 결과 조회로 복구합니다.
- PG 호출은 DB 트랜잭션 밖에서 실행하고, 저장 시 실행권과 완료 결과를 다시 검증합니다.
- 결과 조회는 재전송 횟수에 포함하지 않으며, 재전송 한도에 도달해도 계속합니다.

## 검증

- HTTP·실제 MySQL·로컬 가짜 PG로 동시 승인 복구, 지연 승인, 환불 재전송 보류와 완료 반영 검증
- 실행권 만료·중복 처리·완료 결과 검증·확인 필요 기록 및 롤백 시 로그 미발행 검증
- `./gradlew build` 통과 — 전체 586개 테스트, 실패·오류·건너뜀 없음
- `git diff --check` 통과

## 범위와 한계

- 환불은 최초 전송 이후 결과 조회만 수행하며, 실패한 환불의 자동 재전송은 지원하지 않습니다.
- 전송 시작 기록 직후 중단되면 PG에 요청이 도착하지 않았더라도 재전송을 보류할 수 있습니다.
- 확인 필요 건은 DB·로그로만 남기며, 운영자 재실행 API·외부 알림은 제공하지 않습니다. 커밋 직후 종료 시 로그는 누락될 수 있습니다.
- GET 승인 재시도로 응답이 지연될 수 있으며, 10분 이후에도 결과가 불확실하면 좌석 점유를 유지합니다.
- 로컬 가짜 PG로 검증했으며, 실제 Toss 거래·멱등성 검증은 별도로 필요합니다.
